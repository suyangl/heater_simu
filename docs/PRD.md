# PRD：HeatSimu France — 法国家庭电暖器局部加热与电费 3D 模拟器

| 项目 | 内容 |
|---|---|
| 版本 | v0.5（个人本地版：Windows 10 + Docker Desktop，localhost 访问、无账户、非商用） |
| 仓库 | suyangl/heater_simu |
| 仿真引擎 | OpenFOAM v2406（ESI / openfoam.com，免费开源 GPL） |
| 使用方式 | 个人本地使用、非商用：`docker compose up` → 浏览器打开 `http://localhost:8080` |
| 场景 | 法国家庭（公寓 / 独栋）电采暖 |
| 状态 | 待评审 |

## 1. 背景与问题

- 法国约 **1/3 的主要住宅使用电采暖**（convecteur、panneau rayonnant、radiateur à inertie 等），冬季电费是家庭最大的能源支出之一。
- 电价结构复杂：**Tarif Bleu Base / Heures Pleines–Heures Creuses (HP/HC) / Tempo（蓝/白/红日）**，用户很难判断"什么时候开、开多大、开在哪"最划算。
- 大量老旧住房 **DPE 能源等级为 E/F/G（"passoires thermiques"）**，热损失大，但用户缺少直观工具理解"热量去哪了"。
- 现有工具（电费计算器、ADEME 简易模拟器）只给一个总数，**不考虑房间几何、家具遮挡、电暖器位置、局部舒适区**，也没有可视化。

**核心洞察**：很多人其实只需要"床边 / 书桌前"暖和，而不是整个房间 21°C。局部加热 + 合理放置 + 合理时段 = 显著省电。

## 2. 产品目标

1. 用户 5 分钟内画出自己的房间（长、宽、高、门窗、家具），放置电暖器。
2. 基于 OpenFOAM 计算房间内 **3D 温度场与气流**，以酷炫的 3D 可视化呈现"哪里暖、哪里冷"。
3. 结合用户输入的电价与 DPE 等级，计算 **日 / 月 / 采暖季电费**。
4. 自动生成 **省电方案**（调温、定时、换位置、换类型、选电价套餐），并量化每项节省（€ 和 kWh）。

### 非目标（v1 不做）
- 不做整栋多房间耦合仿真（v2 考虑）。
- 不做热泵 / 燃气 / 木材采暖（v2 可扩展）。
- 不替代官方 DPE 认证，结果仅供参考。
- 不接入 Linky 实时数据。
- 不做用户账户、登录、云端部署、分享链接、商业化。
- 不自动抓取电价：电价全部由用户手动输入。
- 天气只考虑室外温度（不考虑湿度、风速、日照）。

## 3. 目标用户与场景

个人本地工具，使用者就是作者本人（以及在自己电脑上运行它的家人朋友）。典型场景：
- 只有一台 convecteur 的卧室 / Studio，想知道放哪里、开多大、开几点最省钱；
- 对比 Base / HP-HC / Tempo（价格由自己从合同里抄写）；
- 评估换蓄热式电暖器或加窗帘、门缝条值不值；
- 看 3D 热量分布，直观理解"热量去哪了"。

## 4. 用户故事（User Stories）

- US1 作为用户，我可以 **输入房间长 × 宽 × 高**（米，精度 0.01），或在 2D 画布上 **拖拽绘制** 房间轮廓，两种方式实时同步。
- US2 我可以添加 **家具长方体**（床、书桌、衣柜、沙发、书架、自定义），可在画布拖拽 / 缩放 / 旋转（90° 步进 + 自由角度），也可直接输入长、宽、高、位置坐标。
- US3 我可以添加 **门、窗**（指定所在墙、宽度、高度、离地高度、窗户类型：单层 / 双层 / 三层玻璃）。
- US4 我可以添加一台或多台 **电暖器**：选择类型、功率、位置（贴墙 / 离地高度）、朝向、温控设定（Confort / Eco / Hors-gel，设定温度）、时间计划。
- US5 我可以选择 **DPE 能源等级（A–G）**，或在高级模式中直接输入墙体 U 值、换气次数。
- US6 我可以选择 **电价套餐类型**，并 **自己输入** 每个价格（€/kWh、订阅费 abonnement、HC 时段、Tempo 天数分布）。
- US7 我可以 **输入室外温度**（单一设计温度，或按月平均温度表）；可选一键从 Météo-France 数据获取当地温度。
- US7b 我可以选择 **楼层**（底层 / 中间层 / 顶层 / 独栋）以及楼上楼下是否采暖。
- US8 我可以定义 **舒适区（Zone de confort）**，例如"床上方 0.5–1.2 m"或"书桌椅子区域"，系统评估该区域温度是否达标。
- US9 点击"模拟"后，我能看到 3D 房间，带 **温度切片、等温面、气流粒子/流线、热像仪风格** 的可视化，可旋转缩放、拖动切片高度。
- US10 我能看到 **电费结果**：每小时功率曲线、每日 / 每月 / 采暖季费用、按电价时段分解。
- US11 我能看到 **省电建议列表**，每条带"预计节省 €/年、kWh/年、舒适度影响"，并可一键"应用此方案"重新模拟对比。
- US12 我可以把项目 **保存到本地**（浏览器 localStorage + 导出/导入 JSON 文件），并导出截图 / PDF 报告。

### 5.2 电暖器配置

| 类型（法语） | 中文 | 典型功率 | 物理建模要点 |
|---|---|---|---|
| Convecteur électrique | 对流式（"grille-pain"） | 500–2000 W | ~90% 对流 + 10% 辐射；热空气直接上升，易分层 |
| Panneau rayonnant | 辐射板 | 500–2000 W | ~50% 辐射 + 50% 对流 |
| Radiateur à inertie (fluide / sèche / pierre) | 蓄热式 | 750–2000 W | 有热容，输出平滑，延迟响应；辐射比例较高 |
| Radiateur soufflant / soufflant céramique | 暖风机 | 1000–2500 W | 强制对流，有出风速度和方向 |
| Panneau infrarouge | 红外板 | 300–1200 W | 主要辐射，可吸顶安装 |
| Sèche-serviettes | 浴室毛巾架 | 300–1000 W | v1 可选 |

可配置项：
- 类型、额定功率（W，可自由输入）、尺寸（预设随类型变化，可改）、位置（贴哪面墙、沿墙偏移、离地高度）、是否放在窗下。
- 温控：恒温器类型（机械 bimétal ±1.5°C / 电子 ±0.2°C）、设定温度、**fil pilote 模式**：Confort（如 19°C）、Eco（Confort −3.5°C）、Hors-gel（7°C）、Arrêt。
- 时间计划：每周 7×24 小时的模式表（拖拽刷选）；支持"HC 时段预热"（蓄热式）。
- 高级：对流/辐射比例、热容（蓄热式）、风速（暖风机）可手动覆盖。

### 5.3 建筑围护与能源等级（DPE）

- 用户选择 DPE 等级 **A–G**（依据 2021 年后 DPE 双阈值，能耗 kWh_EP/m²/年：A ≤70，B ≤110，C ≤180，D ≤250，E ≤330，F ≤420，G >420）。
- 系统将等级映射为默认围护参数（**可在高级模式覆盖**）：

| DPE | 外墙 U (W/m²K) | 窗 U (W/m²K) | 换气次数 ACH (1/h) | 典型描述 |
|---|---|---|---|---|
| A | 0.15 | 0.8 | 0.3 | 新建 RE2020，三层玻璃 |
| B | 0.25 | 1.1 | 0.4 | BBC 级 |
| C | 0.35 | 1.4 | 0.5 | 近年翻新 |
| D | 0.6 | 2.0 | 0.6 | 1990 年代 |
| E | 1.0 | 2.8 | 0.7 | 1970–80 年代，部分隔热 |
| F | 1.5 | 3.5 | 0.9 | 少量隔热，旧双层玻璃 |
| G | 2.2 | 5.0 | 1.2 | 无隔热，单层玻璃 |

> 以上为产品默认假设，需在实现阶段由热工顾问 / 文献（如 TABULA/EPISCOPE 法国建筑类型库）校准。

- 每面墙可标记：**外墙 / 与已采暖邻居相邻 / 与未采暖空间相邻（楼梯间、车库）**，分别采用不同边界条件。
- 地板 / 天花板：楼上楼下是否采暖；顶层/底层（如地下室、屋顶）。

### 5.4 电价参数（全部由用户输入）

系统 **不内置、不抓取** 任何电价；只提供输入表单，用户照自己的电费合同 / 账单填写。表单字段为空时不能计算电费（3D 温度场仍可查看）。

| 套餐 | 用户输入的字段 |
|---|---|
| Base | 电价 €/kWh；订阅费 €/月；订阅功率 kVA |
| HP/HC | HP 电价、HC 电价；HC 时段（可分两段，如 22:00–06:00 或 01:00–07:00 + 12:00–14:00）；订阅费 |
| Tempo | 蓝/白/红 × HP/HC 共 6 个电价；每季蓝/白/红天数（自填）；HC 时段；订阅费 |
| 自定义 | 24 h × 7 天的分时电价表 |

- 支持保存多个"电价档案"以便对比套餐（存本地）。
- 订阅功率检查：所有电暖器同时开启的功率超过订阅 kVA 时给出跳闸提示。

### 5.5 室外温度与楼层

**室外温度（只考虑温度）**
- 手动输入：单一室外设计温度（如 5°C，用于 3D 稳态温度场），以及可选的采暖季 **月平均温度表**（10 月–4 月，用于季节电费）。
- 可选自动填充：输入城市 / 邮编，从 Météo-France 数据获取温度。实现方式（二选一，均免费）：
  - Météo-France 官方 API 门户（portail-api.meteofrance.fr），免费注册得到 API key，填在本地 `.env`；
  - Open-Meteo（提供 Météo-France 模型数据，免 key，个人非商用免费）——默认采用，最简单。
- 离线时仍可手动输入，不依赖网络。
- 湿度、风速、日照不纳入 v1；换气（ACH）按 DPE 固定默认值，可手动修改。

**楼层与上下邻接**

| 楼层情况 | 地板边界 | 天花板边界 | 说明 |
|---|---|---|---|
| 底层（rez-de-chaussée），下方为土壤 / 地下室 / 车库（未采暖） | 对未采暖空间或地面传热（U_floor，按 DPE 默认） | 楼上采暖则近似绝热 | 地板冷，脚部不舒适，局部加热价值高 |
| 中间层，上下都有采暖邻居 | 近似绝热 / 邻居温度（默认 19°C） | 同左 | 热损失最小 |
| 顶层（dernier étage），上方为屋顶 / 阁楼 | 楼下采暖则近似绝热 | 对屋顶 / 未采暖阁楼传热（U_roof，按 DPE 默认） | 热空气上升聚在天花板，顶层损失大 |
| 独栋（maison individuelle） | 地面 | 屋顶 | 两侧都有损失 |

- 用户输入：楼层号 / 总楼层，或直接选"底层 / 中间层 / 顶层 / 独栋"；楼上楼下是否采暖；邻居是否长期无人（采暖较少）。

### 5.6 仿真（详见第 7 节）

- **实时模式（默认，毫秒级）**：调用由 OpenFOAM 离线数据训练的代理模型，用户拖动任何参数滑块即刻更新 3D 温度场与电费。
- **精算模式（异步，分钟级）**：当布局超出代理模型可信范围或用户主动点击"精算"时，后台运行 OpenFOAM，完成后推送并替换为高精度结果。
- 电费：代理模型输出维持设定温度所需功率与舒适区温度 → RC 季节模型 → 逐时电价计费。
- 结果缓存（参数哈希）；精算结果回流训练集。

### 5.9 省电规划器（核心卖点）

系统自动生成候选方案 → 用代理模型 + RC 模型批量模拟 → 按 **节省 €/年** 排序，同时显示舒适度影响和投入成本：

| 类别 | 示例建议 | 量化方式 |
|---|---|---|
| 设定温度 | 室温降 1°C（ADEME 经验：约省 7%） | 模型计算 |
| 时间计划 | 外出 / 夜间切 Eco；起床前 30 min 预热 | 模型计算 |
| 电价套餐 | Base → HP/HC 或 Tempo 的年度对比；Tempo 红日减少用电策略 | 逐时费用 |
| 局部加热 | 只保证舒适区温度，降低整体设定温度 + 小功率红外板对准书桌 | CFD 校准 + 模型 |
| 位置 | 电暖器移到窗下 / 移开被沙发挡住的位置 / 不要放在床后面 | CFD 对比 |
| 家具 | 衣柜别贴外墙阻挡辐射；暖气前别放柜子 | CFD 对比 |
| 设备 | 机械恒温 convecteur → 电子恒温 inertie | 模型 + 设备价格 |
| 小改造 | 加厚窗帘、门缝条、窗户贴膜、反射板（电暖器后墙） | 修改 U/ACH |
| 大改造 | 更换窗户、墙体隔热；提示 **MaPrimeRénov'**、CEE 补贴（链接官方网站） | 投资回收期 |

- 每条建议：标题、原理一句话解释、节省 €/年、kWh/年、CO₂（按 RTE 电网平均排放因子，可配置）、舒适度变化、成本、回收期、"应用并对比"按钮。
- **"我的省电计划"**：用户勾选多条建议组合，生成最终计划与 PDF 报告。

### 5.10 项目保存（无账户）

- 无登录、无账户。项目自动保存在浏览器 localStorage，并可导出 / 导入 JSON 文件。
- 后端结果（OpenFOAM 案例、场数据）保存在 Docker 挂载的本地目录 `./data/`。
- 界面语言：中文（默认）+ 英文可选；单位公制，货币 €。

## 6. 信息架构与主要页面

1. **首页（localhost:8080）**：最近项目列表 + "新建项目" + "打开示例房间"。
2. **向导（Wizard）**：① 房间 → ② 门窗 → ③ 家具 → ④ 电暖器 → ⑤ 建筑与 DPE → ⑥ 电价与气候 → ⑦ 舒适区。每步可跳过使用默认值。
3. **编辑器（主工作区）**：左侧工具栏（绘制 / 家具库 / 电暖器库），中间 2D/3D 切换或分屏，右侧属性面板。
4. **结果页**：上方 3D 可视化，下方 KPI + 图表 + 省电建议。
5. **对比页**：最多 3 个方案并排。
6. **报告**：导出截图 / PDF（本地文件）。

## 7. 技术方案

### 7.1 架构原则：前后端分离 + 异步计算 + 结果轻量化（本地 Docker 部署）

目标：**用户调参后 < 100 ms 看到 3D 温度场和电费**。OpenFOAM 不在交互链路上：

1. **离线**：在本机用 OpenFOAM 批量跑参数组合，构建数据集（一次性，可在夜里跑）。
2. **训练**：用数据集训练轻量代理模型（查找表插值 → 降阶模型 → PINN / 神经算子，逐步升级）。
3. **在线**：前端调用代理模型，毫秒级出结果；超出训练范围的布局 **异步** 在本机触发 OpenFOAM 精算，完成后推送高精度结果并回流数据集。

| 服务 | 镜像 / 构建 | 端口 | 说明 |
|---|---|---|---|
| frontend | `node` 构建 → `nginx:alpine` | 8080 → 宿主机 | 静态页面 + 反向代理 `/api`、`/ws` 到 api |

- 一键启动：`docker compose up --build`，然后浏览器打开 `http://localhost:8080`。
- 所有数据在 `./data/`（git 忽略）；仓库内附带一份预训练的 S1 查找表，首次启动即可使用，无需先跑数据集。
- 配置项（`.env`）：`OPENFOAM_NPROCS`、`MAX_PARALLEL_JOBS`、`WEATHER_PROVIDER=openmeteo|meteofrance|none`、`METEOFRANCE_API_KEY`（可选）。
- **目标平台：Windows 10（x86_64）+ Docker Desktop（WSL2 后端）**；Linux 同样可用。
  - 前置：Windows 10 保持最新版本（Docker Desktop 对 Win10 版本有最低要求，以 Docker 官方文档为准）、BIOS 开启虚拟化、安装 WSL2。
  - 资源（**目标机器 8 GB 内存**）：在 `%UserProfile%\.wslconfig` 中设置 `memory=4GB`、`processors=4`（按实际核数调整）、`swap=4GB`；worker 默认 `OPENFOAM_NPROCS=2`、`MAX_PARALLEL_JOBS=1`。
  - 内存预算：OpenFOAM 约 1 GB / 10 万单元（含辐射时更多）→ 默认网格 **10–30 万单元**（背景 8 cm，近电暖器/窗 3 cm）；api + 前端 < 1 GB；浏览器 3D < 1 GB。
  - 性能：OpenFOAM 读写大量小文件，**不要把 `./data` 放在 Windows 盘（C:\ 经 bind mount 很慢）**；默认使用 Docker 命名卷 `heater_data`，或把仓库 clone 到 WSL2 的 Linux 文件系统（`\\wsl$\Ubuntu\home\...`）。
  - 脚本：提供 `start.ps1` / `start.bat`（检查 Docker 是否运行 → `docker compose up -d --build` → 自动打开浏览器 http://localhost:8080）。
  - 换行符：仓库 `.gitattributes` 强制 `*.sh`、OpenFOAM 字典使用 LF，避免 Windows 下 CRLF 导致容器内脚本 / 字典解析失败。
- 具体镜像 tag 以 Docker Hub 上 OpenCFD 发布为准，实现时锁定版本。

### 7.4 后端（物理引擎层）OpenFOAM

| 项 | 方案 |
|---|---|
| 求解器 | `buoyantSimpleFoam`（稳态浮力驱动传热，数据集主力）；`buoyantPimpleFoam`（瞬态，开机升温曲线 / 恒温器开关，少量样本） |
| 计算域 | 房间空气；家具为实体障碍（snappyHexMesh `searchableBox` 挖除，无需 STL） |
| 网格 | 默认（8 GB 内存机器）：背景 8 cm，电暖器/窗户附近细化 3 cm，10–30 万单元；"高精度"档 50 万单元（需 ≥ 16 GB） |
| 物性 / 湍流 | 空气 perfectGas 或 Boussinesq；k-ω SST / realizable k-ε + 浮力修正 |
| 辐射 | `fvDOM` 或 `P1`（辐射板、红外板、蓄热式需要） |
| 电暖器 | 能量源（fvOptions/fvModels 体积热源）表示对流部分 + 高温辐射面；暖风机为出风口/回风口 |
| 围护边界 | 外墙/窗 `externalWallHeatFluxTemperature`（U 值 + 室外温度，h_out 取固定值）；相邻采暖房间绝热/定温；地板/天花板按楼层类型设置（对地面/地下室/屋顶传热或绝热） |
| 湿度 / 风 | 不考虑（只用室外温度）；渗风按 ACH 固定值 |
| 渗风 | 按 ACH 设门窗缝入口/出口，或体积源近似 |
| 计算资源 | 本机运行：每个案例 4–8 核，稳态约 5–15 min；100–200 个案例的 S1 数据集在 8 核电脑上约 1–2 天（可夜间跑，支持断点续跑） |

### 7.5 离线数据集设计（DoE）

> 注意：`DPE=[A, C, G] × 功率=[1000W, 2000W] × 位置=[窗下, 墙角]` 只有 3×2×2 = **12 个组合**。要做到约 100+ 个样本并覆盖真实用户，需扩展维度并用拉丁超立方 / Sobol 采样，而不是只用全因子网格。

**物理降维技巧（大幅减少样本数）**：稳态下温度场近似满足 `T(x) ≈ T_out + ΔT_ref · θ(x)`，无量纲温度场 θ 主要取决于几何、电暖器类型/位置和 Biot 数（≈ 围护 UA 与对流换热之比）。因此：
- **室外温度不需要作为采样维度**（线性平移 + 小修正）。
- **功率与 DPE 可合并为少数无量纲参数**（P/(UA·ΔT)、Rayleigh 数），浮力非线性用少量样本修正。

建议的参数空间（v1）：

| 维度 | 取值 | 类型 |
|---|---|---|
| 房间长 × 宽 | 2.5–6 m × 2.5–5 m（连续），高 2.4–2.8 m | 连续 |
| DPE（→ 墙/窗 U、ACH） | A–G | 有序离散 / 连续 U |
| 功率 | 500–2500 W | 连续 |
| 电暖器类型 | convecteur / 辐射板 / 蓄热式 / 暖风机 / 红外 | 类别 |
| 电暖器位置 | 窗下 / 外墙非窗 / 内墙 / 墙角 + 沿墙偏移比例 | 类别 + 连续 |
| 窗户 | 面积比、所在墙 | 连续 + 类别 |
| 室外温度 | −10 – 15°C（多数情况可用无量纲缩放，不必密集采样） | 连续 |
| 楼层类型 | 底层 / 中间层 / 顶层 / 独栋（→ 地板、天花板边界 U 值） | 类别 |
| 家具 | 用"占用率栅格"编码（见 7.6），训练时随机放置 1–5 个方块（床/桌/柜） | 结构化 |

规模：**阶段 1 约 100–200 个案例**（固定 3–4 种常见房间模板，覆盖 DPE × 功率 × 类型 × 位置）；**阶段 2 约 1000–3000 个**（随机房间尺寸和家具布局），用于泛化。

### 7.6 代理模型（Surrogate）路线

| 阶段 | 模型 | 输入 | 输出 | 推理速度 | 适用范围 |
|---|---|---|---|---|---|
| S1（MVP） | 多维插值查找表（`scipy.interpolate.RegularGridInterpolator` / RBF）+ 物理缩放 | 模板 ID、DPE、功率、类型、位置 | θ 场（规则网格）、舒适区温度、热损失分解 | < 10 ms | 仅模板房间 + 预设家具布局 |
| S2 | 降阶模型 POD/PCA + 回归（高斯过程 / 梯度提升 / 小型 MLP） | 上述 + 房间长宽（几何归一化到单位立方后重采样） | POD 系数 → 重建场 | < 20 ms | 任意矩形尺寸、少量家具 |
| S3 | 3D U-Net / 神经算子（FNO）或 PINN（数据 + 能量方程残差约束） | 3D 栅格：家具占用、电暖器位置/功率、墙体 U、窗户掩码 | 3D 温度场（+ 速度场） | 20–100 ms（WebGPU/服务器 GPU） | 任意用户布局 |

说明与取舍：
- **PINN** 单独用于"多参数 + 任意几何"训练成本高、收敛难，推荐作为 S3 的正则化手段（数据驱动为主、物理残差为辅），而不是 MVP 首选。
- **S1/S2 可在前端直接运行**（JSON 查找表或 ONNX，模型 < 5 MB）；S3 可在 FastAPI 服务端 GPU 推理，或量化后 onnxruntime-web/WebGPU。
- 能耗 / 电费：稳态代理模型给出"维持设定温度所需平均功率"与舒适区偏差 → 输入 RC 季节模型 → 逐时电费，全季 < 50 ms。

### 7.7 置信度与"不确定 → 精算"回退（关键）

用户可以自由画房间和家具，必然会出现训练集没覆盖的布局。设计：
1. 代理模型输出同时给出 **置信度**（输入到训练集的距离 / 集成模型方差 / GP 方差）。
2. 高置信：直接显示，标签"即时结果"。
3. 低置信：仍然即时显示代理结果（标注"预估"），同时 **后台异步提交 OpenFOAM 精算**，WebSocket 推送进度，完成后平滑过渡到精算云图。
4. 每次精算结果 **回流数据集**，定期重训（主动学习），模型越用越准。

| 代理模型无法泛化到用户自定义布局（训练集只覆盖少量组合） | 结果失真、用户不信任 | 物理无量纲化减少维度；随机布局数据集；置信度评估 + 低置信时异步 OpenFOAM 精算；主动学习回流 |
| 本机算力有限，数据集生成慢 | 进度延误 | 仓库附带预训练 S1 查找表；粗网格 + 少量精网格校正；断点续跑、夜间批量 |
| PINN 训练难收敛 | 进度延误 | MVP 不依赖 PINN；先用查找表/POD，PINN 仅作为 S3 物理正则化选项 |
| snappyHexMesh 对任意家具布局失败 | 任务失败 | 前端校验最小间隙（≥ 网格尺寸 2 倍）；失败自动降级为 blockMesh + topoSet/subsetMesh 挖除方块 |
| 求解发散（浮力流） | 任务失败 | 预设松弛因子、先跑低 Ra 再升温的初始化策略；自动重试 |
| DPE → U 值映射不准 | 电费偏差 | 允许用户输入实际年度用电量校准模型（"我去年电费 X €"） |
| 天气接口不可用 | 无法自动填温度 | 本地缓存；手动输入温度始终可用 |
| Windows 10 + Docker Desktop 环境问题（WSL2 未开启、内存不足、文件 IO 慢、CRLF） | worker 无法运行或很慢 | 启动脚本自检；命名卷存数据；`.wslconfig` 指南；`.gitattributes` 强制 LF |
| 3D 效果在低端设备卡顿 | 体验差 | 自动降级（关闭体渲染、粒子数自适应） |

## 12. 已确定 / 待决问题

已确定：
- OpenFOAM：ESI v2406（openfoam.com，免费 GPL，官方 Docker 镜像）。
- 部署：本地 docker compose，localhost:8080，无账户，个人非商用。
- 电价：全部由用户输入，不内置、不抓取。
- 天气：只用室外温度（手动输入，可选自动获取）。
- 运行平台：Windows 10 + Docker Desktop（WSL2），8 GB 内存。

待决：
1. 代理模型推理放前端（onnxruntime-web）还是放 FastAPI？——本地部署下两者都可，倾向 S1/S2 放前端、S3 放 api。
2. CPU 核数？（已知 Windows 10 x86、8 GB 内存）——决定数据集生成时间。
3. 舒适度只用温度阈值（建议），还是需要 PMV/PPD？
